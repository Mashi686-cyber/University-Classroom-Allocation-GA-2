# Main Experimental Evaluation

## 1. Experimental Objective
The objective of this phase is to evaluate the performance of the Genetic Algorithm (GA) against a simple sequential baseline heuristic, measuring its ability to reduce conflicts, maximize utilization, and allocate courses.

## 2. Research Questions
- **RQ1**: Is it possible to use Genetic Algorithm in reducing conflicts in classroom allocation?
- **RQ2**: Is it possible to optimize the usage of existing classrooms through Genetic Algorithm?
- **RQ4**: Does the GA-based classroom allocation approach outperform the simple classroom allocation approach?

## 3. Dataset Configurations
The evaluation was conducted on three strictly generated synthetic datasets:
- **Small**: 20 courses, 10 classrooms, 20 timeslots
- **Medium**: 50 courses, 15 classrooms, 25 timeslots
- **Large**: 100 courses, 20 classrooms, 30 timeslots

## 4. Baseline Methodology
The baseline acts as a greedy sequential allocator, placing each course into the first physically available and temporally open classroom without backtracking. It prioritizes speed but frequently creates lecturer and student group overlaps because it has no global view of the schedule.

## 5. GA Configuration
Based on the preliminary Phase 5 parameter study, the following configuration was selected:
- **Population Size**: 50
- **Generations**: 50
- **Crossover Rate**: 0.8
- **Mutation Rate**: 0.1
- **Elitism**: 2

## 6. Random Seeds
To capture the probabilistic nature of the GA, 5 independent runs were performed per dataset using seeds: `[42, 43, 44, 45, 46]`. The reported GA metrics represent the mean across these 5 runs. The baseline is deterministic and required only a single run.

## 7. Evaluation Metrics
- **Hard Constraints**: Total Conflicts (Lecturer + Student Group + Classroom), Capacity Violations, Room Type Violations, Unallocated Courses.
- **Soft Objectives**: Classroom Utilization (%).
- **Operational Costs**: Execution Time (seconds).

## 8. Comparison Methodology
Both algorithms were evaluated using the exact same programmatic metric definitions (`ConstraintChecker` and `MetricsCalculator`). 

## 9. Results

**SMALL Dataset**
- **Baseline**: Alloc: 17, Conflicts: 8, Util: 71.0%, Exec: 0.00s
- **GA (Mean)**: Alloc: 17, Conflicts: 0, Util: 70.9%, Exec: 0.32s

**MEDIUM Dataset**
- **Baseline**: Alloc: 36, Conflicts: 5, Util: 53.6%, Exec: 0.00s
- **GA (Mean)**: Alloc: 36, Conflicts: 0, Util: 61.1%, Exec: 0.72s

**LARGE Dataset**
- **Baseline**: Alloc: 51, Conflicts: 7, Util: 63.2%, Exec: 0.00s
- **GA (Mean)**: Alloc: 51, Conflicts: 0.6, Util: 68.9%, Exec: 1.16s

## 10. Observations
- **Conflicts**: The GA essentially eradicated conflicts on Small and Medium (100% reduction) and practically eliminated them on Large (91.4% reduction, down to an average of 0.6 conflicts).
- **Utilization**: The GA significantly boosted utilization on Medium (+14.1%) and Large (+8.9%) while avoiding the massive conflicts generated by the Baseline.
- **Unallocated**: Both algorithms allocated the exact same number of courses across all sets. The unallocated courses are mathematically impossible to schedule given the randomly generated capacity and room-type constraints in the datasets.
- **Scalability**: Execution time scaled sub-linearly relative to dataset size (Small 0.32s -> Large 1.16s). 

## 11. Limitations
The GA is drastically slower than the baseline (1.16 seconds compared to near-instantaneous 0.004 seconds). While absolute execution time remains well within acceptable limits for a university schedule, the computational overhead is undeniably higher. Furthermore, the synthetic datasets produced heavily constrained physical limits that capped allocation for both algorithms, potentially masking the GA's ability to schedule a fully valid 100% load.
